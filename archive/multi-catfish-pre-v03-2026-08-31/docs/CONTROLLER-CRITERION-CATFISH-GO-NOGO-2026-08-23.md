# 判準:B17 第一題的三分讀法(2026-08-23)

**這份文件在訓練結果回來之前寫定。** 它規定崩潰四項要怎麼讀、什麼結果算 catfish 有必要。

⛔ **看到數字之後不得修改。** 要改就在數字回來之前改。
⛔ **設計 catfish 機制的一方不得修改本文件。** 它是唯讀輸入。

理由:凍結檔已經把崩潰**怎麼量**凍得很細(四項指標、正規化、兩個取樣點、貪婪 vs 執行、
排除規則),但 `thresholds` 區段**沒有任何崩潰門檻**,整份凍結檔也找不到綁在 collapse
上的數值。也就是說訓練會拿回四個數字而沒有事先承諾的讀法。同一份凍結檔對
`outage_dropped_transition_rate` 寫過這件事的理由:

> It must be frozen BEFORE P1 because choosing it after seeing the rate is the leak §7.1 names.

同樣的理由適用於此,先前未被套用。本文件補上。

---

## 1. 兩個族,不是四個指標

四項指標分成兩族,**它們可以分離,而那個分離本身有意義**:

| 族 | 指標 | 崩潰方向 | 量的是 |
|---|---|---|---|
| **動作族** | `active_beam_count` | ↓ | 行為集中:實際選出的動作有多集中 |
| | `argmax_agreement` | ↑ | |
| **Q 族** | `q_margin`(正規化) | ↑ | 表徵集中:Q 曲面有多尖、多一致 |
| | `q_entropy` | ↓ | |

**為什麼要分族:** 行為集中可以是環境造成的 —— 若只有少數波束是好的,任何合理策略都會
集中,那不是同質化,catfish 也不是對的工具。shared-Q 的病理是**表徵**同質化:
使用者選一樣的東西是因為他們的 Q 曲面一樣。**兩族都動,才是 B17 第一題問的那個崩潰。**

⇒ 判準建立在「哪一族動了」,不是「四項裡動了幾項」。

## 2. 尺規:null 與飽和

每一項指標正規化到 [0, 1]:

- **null(0)** = **第 0 回合的 `collapse_first` 貪婪讀數**。網路未訓練 ⇒ argmax 接近隨機,
  而它與後續讀數共用同一組候選結構、同樣的使用者數與波束數。
  **同一次 run 內就有,不需要額外計算。**
- **飽和(1)** = 完全崩潰的解析值:`active_beam_count = 1`、`argmax_agreement = 1`、
  `q_entropy = 0`;`q_margin` 取其正規化上界 1。

**移動量** = (讀數 − null) / (飽和 − null),朝崩潰方向為正。

⚠ 這個尺規只在 null 有意義時成立。若第 0 回合的讀數本身就已接近飽和,
表示候選結構本身就強制集中 —— **那要當成第 4 節的不可讀情形處理,不是「崩潰」。**

## 3. 判準(三分)

取**最後 1000 回合**的 `collapse_first` 移動量中位數(`ε` 在第 2000 回合就降到 0.01,
最後 1000 回合已穩定)。一族視為「動了」= 該族**兩項都**達到門檻。

| 結果 | 條件 | 讀法 |
|---|---|---|
| **有必要** | **兩族都**移動 ≥ **0.50** | 同質化存在且是表徵層的。catfish 的前提成立,可以進入機制選擇 |
| **不必要** | **兩族都**移動 < **0.20** | 同質化不存在。B17 警告的分支發生 ⇒ **整條貢獻線重想**,不是調參數 |
| **不確定** | 其餘(恰一族動、或落在 0.20–0.50) | 見下,不得自行歸類到上面兩格 |

### 「不確定」的兩種形狀,處置不同

- **只有動作族動** ⇒ 集中是環境造成的,不是 shared-Q 造成的。
  **catfish 是錯的工具**,要先解釋為什麼候選結構本身就窄(參考:`|A_u| = 28`、V = 39)。
- **只有 Q 族動** ⇒ 表徵確實同質化,但遮罩或環境擋住了它表現成行為。
  catfish 的前提**可能**成立,但示範需要另一個設定 —— 要先找到一個讓它表現出來的情境,
  否則機制有效與否無法量測。

⚠ **0.20 與 0.50 是承諾,不是推導。** 它們沒有第一原理來源,選這兩個值的理由是:
0.50 是「走完一半以上」的自然分界;0.20 要低到足以讓「幾乎沒動」不被誤判成有訊號,
又高到不會被雜訊觸發。**重點不在數字對不對,在它先於數據。**

## 4. 不可讀的四種情形(遇到就是回報,不是判斷)

1. **四項全零。** 那是「什麼都沒量到」。程式在缺樣本時會拋錯而不回報零,
   所以若真的看到零,那是真的零 —— 但仍要先確認取樣有發生。
2. **只看 `collapse_drift`。** `steps_per_episode = 10` ⇒ 兩點只隔 9 步 ≈ 4.5 分鐘,
   **`collapse_drift ≈ 0` 不可讀成「不崩潰」**。本判準用 `collapse_first` 的絕對水準,
   `collapse_drift` 只作為佐證,不單獨構成結論。
3. **用執行版。** `*_executed` 不得用於本判準。`ε` 要 2000 回合才降到 0.01,
   前五分之一量到的主要是隨機策略。B17 第一題問的是**策略**,貪婪版才回答它。
4. **`α = 0.01` 那一臂中止。** 那是 G-11 的預期行為,**不是一個資料點**,
   不得計入任何一族的判斷。

## 5. 這份判準管不到的事

它只回答「同質化存不存在」。它**不**回答:機制該長什麼樣、哪個機制比較好、
效果有多大。那些要在「有必要」分支成立之後,用另一組事先承諾的比較設計來答。
