# ⛔ 裁決 1:`H = 10` —— 而且有一件事會改變你的選項空間

## 1.1 你要的三個數字(已在 `docs/W18-REPLY-2026-08-22.md`,這裡只留結論)

100 使用者 × 10 episode,凍結常數,`stay-if-possible`,9,000 個段內連續步樣本:

| 量 | p50 | p95 | max |
|---|---|---|---|
| `\|Δθ\|` / 步 | 0.0067° | 0.0190° | 0.0278° |
| Δ增益 / 步 | +0.0037 dB | +0.0588 dB | +0.1037 dB |
| **累積 3.010 dB 需要** | **169 步** | 46 步 | **29 步(最快)** |

segment 結束原因:**episode reset 100.0%**(handover 0、outage 0、unserved 0)。
段長 p50 = p95 = max = **10 步**。段內最大跌幅 **0.718 dB = 預算的 24%**,p50 只有 0.026 dB。

⇒ **`p(t)` 在一個 episode 內基本上等於 `p⁰`。** 你的假設成立,而且比你寫的極端:
最樂觀差 2.9 倍,典型差 17 倍。

## 1.2 ★ 你可能還沒把這件事算進去:**`β = 0.9` 已經把有效視野釘死在 10 步**

這是我認為最關鍵的一點,因為它讓「把 `H` 加大」這個直覺解**單獨無效**:

```
有效視野 = 1/(1−β) = 1/(1−0.9) = 10 步
```

| `H` | `β^(H−1)`(最後一步的折扣權重) | 前 10 步佔總折扣權重 |
|---|---|---|
| **10**(Table I) | 3.87e−01 | 100.0% |
| 30 | 4.71e−02 | 68.0% |
| **170**(涵蓋 p50) | **1.85e−08** | **65.1%** |
| 378(整個 ≥10° 服務窗) | 5.62e−18 | 65.1% |

**把 `H` 從 10 拉到 170,前 10 步仍然佔 65% 的折扣權重,而第 170 步的權重是 1.8e−8。**
也就是說 agent 會**經歷**遞推,但永遠不會因為它**被計分**。

要讓有效視野對上 169 步,需要 `β ≈ 0.994`。而 `β = 0.9` 是 **Table I 明載(P 級)**,
SDD F1 還特別寫了「`H = 10` 與 `β = 0.9` 自洽」。

⇒ **`H` 與 `β` 必須一起動,而動 `β` 是對一個 P 級值的重大偏離。**

## 1.3 四個選項與各自的代價

### (a) 維持 `H = 10`、`β = 0.9`,**揭露機制在 episode 內不作用**

- **代價**:角度感知功率遞推 —— 本論文第一個貢獻 —— 在 episode 內是**裝飾性的**。
  `r1` 實際退化成「固定 `p⁰` 下的吞吐量 / 系統功率」。
  `r2` 也幾乎沒東西可做(穩定策略十步內零換手)。
- **好處**:與 MODQN baseline 完全可比,零偏離。

### (b) 加大 `H`,**不動 `β`**

- ⛔ **我認為這是無效解**,見 §1.2:第 170 步權重 1.8e−8。
  它會讓 episode 變長 17 倍(訓練成本 ×17)而換到幾乎零的信用分配。

### (c) 加大 `H` **且**加大 `β`(例如 `H = 170`、`β = 0.994`)

- **代價**:`β` 是 Table I 的 P 級值,改它是**新的 `X` 級偏離**,
  而且會同時改變 MODQN baseline 的行為 ⇒ **可比性受影響,不只是我們這邊變**。
  訓練成本 ×17。
- **好處**:機制真的被運動、也真的被計分。

### (d) ★ **維持 `H`、`β`、`Δt` 全部不變,改為「暖啟動 segment」**

**這是我的建議。** 理由是它有一個**本專案已經用過的、完全對應的前例**。

問題的實際形狀不是「episode 太短所以 `p` 不會變」,而是
**「每個 episode 都從 `p = p⁰` 開始,所以 `p` 的分布是錯的」** ——
100% 的 segment 由 episode 邊界切斷,代表 `p(0) = p⁰` **恆真**,
而那是 episode 邊界的**人工產物**,不是幾何的性質。

**前例逐字對應**:W-04 為什麼要在 step 0 之前把 D2 latch 暖機?
`docs/PROVENANCE.md` 與 `env/scenario.py` 的理由是

> 「冷 latch 會讓每個 episode 的第一步都是空遮罩,而那是 **episode 邊界的人工產物,
> 不是幾何的性質**。」

**功率 segment 現在的處境一模一樣。** 冷 segment 讓每個 episode 的 `p(0) = p⁰`
是 episode 邊界的人工產物。

若在 step 0 之前把 segment 暖機,`p(0)` 就會**跨 episode 分布在整個 3 dB 預算上**,
於是 `r1` 看得到 `p` 的完整動態範圍 —— 即使**單一** episode 內 `p` 仍只移動 0.03–0.7 dB。

- **代價**:`H`、`β`、`Δt`、`p⁰`、`p_max` 全部不動 ⇒ **零可比性影響**。
  但初始狀態分布會依賴一條暖機規則,那條規則必須凍進 PREREG。
- **限制(必須誠實說)**:它讓**狀態分布**正確,但**不會**讓 agent 學到遞推的
  *動態* —— `β = 0.9` 本來就不會給那個信用。若你要的是「agent 學會預期增益下降」,
  只有 (c) 做得到。

**⚠ 一個 (d) 的實作岔路需要你一起裁:暖機期間用什麼決定 segment 歸屬?**
D2 暖機不需要策略(它是逐 NORAD 的幾何);但功率 segment 需要知道「這幾步握著哪條鏈路」。
兩條路:

- **(d1)** 暖機期間跑**參考策略** ⇒ 初始分布變成**策略相依**,那是一個真實的方法論選擇;
- **(d2)** 直接抽 `τ`(段已經跑了幾步),再從那時的幾何取 `G^T(θ(τ))` ⇒
  不需要策略,但需要凍一條 `τ` 的抽樣分布。

**我傾向 (d2)**,因為它不把策略灌進初始分布;但抽樣分布是 `S` 級,要你定。

## 1.4 請裁決

**(a) / (c) / (d1) / (d2) / 其他。** 若選 (d),請一併裁 `τ` 的抽樣分布或暖機長度。

# 小問題:`L_s` 的對數常態偏差要不要正規化?

C-8 要求「零均值、dB 域高斯」,我照做了。但 dB 高斯換算成線性是**對數常態**:

```
E[10^(−L_s/10)] = exp((σ·ln10/10)²/2)      σ = 3 dB 時約 +1.0 dB 的平均增益
```

也就是「零均值遮蔽」實際上讓平均接收功率**上升約 1 dB**。

**我照留不正規化**,因為正規化會讓「0 dB 遮蔽」相對於每一份已發表的 NTN 鏈路預算
悄悄改變意義 —— 但它被寫進 docstring 並由測試釘住(實測對上解析預測,rel < 2%),
免得有人從一個意外慷慨的 EE 數字反推出來。

**確認照留,還是要我改成單位線性均值?** 一行的事。
(對照:`K_R` 的 Rician 抽樣我**是**做了單位均值正規化,理由是衰落應該**重分配**
確定性鏈路預算的功率而不是平移它。兩者現在慣例不同,這本身也許值得統一。)
