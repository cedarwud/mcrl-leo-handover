### 為什麼是暖啟動造成的

冷啟動下每個 segment 都從 `p⁰ = 0.825 W` 起跑,只有一半的預算高度;
暖啟動讓 segment 帶著已經累積的補償進場,於是**進場時就已經在預算中段**,
再走一小段惡化的幾何就會撞頂。

**這正是你預告的那件事:「若兩臂的頭條結論不同,那本身就是要報告的發現。」**
它立刻發生了,而且不是在頭條指標上,是在**約束會不會 binding** 這件事上。
兩臂的差別不是 ±幾個百分點,是 **0.0000 vs 0.0079** —— 一個說約束不存在,
一個說約束是活的。

⚠ 而且方向正如你更正我的:主臂(`Uniform{0..H−1}`,`H=10 > L=5`)**高估**段齡,
所以它是**讓約束更容易開火**的那一臂。敏感度臂會給出更接近冷啟動的結果。
**兩臂都要跑,結論要一起報。**

## 3. Q-E ⇒ **凍 `N = 3`,而且沒有跑 P2**

準則你已核准。它需要的唯一數字是 **re-key 率**,而那是**情境特徵化**、
在任何策略被評估之前就存在 —— 不是 probe 輸出。所以 Q-E 直接關閉:

| `N` | re-key 率 @ 30.08 s | ≤ 5%? |
|---:|---:|---|
| 2 | 2.708% | ✓ |
| **3** | **3.819%** | ✓ ← 最大的符合者 |
| 4 | 5.417% | ✗ |

`DWELL_N_IS_FROZEN = True`。**`N = 3` 的數值沒變,變的是它的地位** ——
它從「sweep 中點的佔位值」變成「規則按自己的條件回傳的值」,
而 docstring 與測試都把這個區別寫出來了(它當了好幾週的佔位值,
所以「本來就在那裡」正是要防的失效模式)。

**P2 改為敏感度 probe,`closes: []`。** 跑一個結論已定的 probe
等於把一個已決定的數字包裝成實驗結果。

剩下 **Q-D 一項開著**,由 P3 關閉;`assert_ready_to_train()` 仍正確地擋著。
