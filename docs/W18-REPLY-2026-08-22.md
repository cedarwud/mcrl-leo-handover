### ⚠ 一件你沒提、但我實作時撞到的:dB 域零均值 ≠ 線性域零均值

dB 高斯換算成線性是**對數常態**:

```
E[10^(−L_s/10)] = exp((σ·ln10/10)² / 2)     σ = 3 dB 時約 +1.0 dB 的平均增益
```

也就是「零均值遮蔽」實際上會讓平均接收功率**上升約 1 dB**。

**我照留、不正規化**,因為正規化會讓「0 dB 遮蔽」相對於每一份已發表的 NTN 鏈路預算
悄悄改變意義。但它被寫進 docstring 並由測試釘住(實測 mean linear gain 對上解析預測,
rel < 2%),免得有人從一個意外慷慨的 EE 數字反推出來。**若你要正規化,說一聲,一行的事。**

## 2. 裁決 (a)(b) 照辦。**(c) 的答案是:需要 169 步,而 episode 只有 10 步。**

沒有動 `p⁰`、`p_max`、`H`、遮罩門檻、`θ_3dB`、格集。

### 你要的三個數字(100 使用者 × 10 episode,凍結常數,`stay-if-possible`)

**(1) 每步 `Δθ` 與換算的增益變化**(9,000 個「段內連續兩步」樣本):

| | p50 | p95 | max |
|---|---|---|---|
| `\|Δθ\|` | 0.0067° | 0.0190° | 0.0278° |
| Δ增益 | +0.0037 dB | +0.0588 dB | +0.1037 dB |

只有 **60.4%** 的步增益在下降(其餘在上升 —— 衛星還在接近時偏軸角是**縮小**的)。

**(2) 累積 3.010 dB 要幾步**(只算下降中的那些步):

| 速率 | dB/步 | 步數 | 秒 | 分 |
|---|---|---|---|---|
| 下降步的 **p50** | 0.0178 | **169** | 169 | **2.8** |
| 下降步的 p95 | 0.0658 | 46 | 46 | 0.8 |
| **觀測到的最快** | 0.1037 | **29** | 29 | 0.5 |

**(3) segment 為什麼結束:**

| 原因 | 次數 | 佔比 |
|---|---|---|
| **episode reset** | **1000** | **100.0%** |
| handover | 0 | 0.0% |
| outage | 0 | 0.0% |
| unserved | 0 | 0.0% |

segment 長度 p50 = p95 = max = **10 步**。**每個使用者每個 episode 恰好一個 segment,
而它總是被 episode 邊界切斷。**

### 結論:你的假設成立,而且比你寫的更極端

> 「如果答案是『需要遠超過 10 步』,那會是比遮罩不作用嚴重得多的問題。」

**答案是:典型 169 步,最快也要 29 步。** `H = 10` 連**最樂觀**的情況都差 2.9 倍,
典型情況差 **17 倍**。

而且不只是閘不觸發 —— **遞推本身在 episode 內幾乎不動**:
段內最大跌幅 0.718 dB,是 3.010 dB 預算的 **24%**,而那還是十步全程累積的結果。
p50 只有 0.026 dB。**`p(t)` 在一個 episode 內基本上等於 `p⁰`。**

### 一個支持你診斷的量級對照

169 s = **2.8 分**,而量測到的 **≥10° 仰角服務窗是 6.3 分(378 s)**。
所以 3 dB 預算大約在一次 pass 走到 **45%** 時被吃掉 ——
**這個機制是照著 pass 的尺度設計的,而 episode 是 10 秒,差約 38 倍。**

換句話說:`p⁰ = p_max/2` 的 3 dB 預算**尺度是對的**(對著 pass),
出問題的是 `H`,不是預算。這反過來支持「不要動 `p⁰`」。

## 3. `A_u(t)` **可以**是 `𝒞` 的真子集 —— 是 (i) 情境太寬鬆,不是 (ii) 建構冗餘

### 為什麼建構上不冗餘

遮罩的三項在 `build_slot_table` 裡是 **AND** 起來的,而它們**在候選表建好之後才評估**:

```
mask[a] = 槽 l 已佔用  AND  格 j 存在  AND  格 j 看得到衛星 l
```

關鍵在於 `assign_satellite_slots` **不預先過濾**:它拿 D2 給的東西,
**不足四顆就把槽留空**;而 `_cell_visibility` 是在槽填好**之後**算的,不是之前。
所以三項都有真正刷掉格子的能力。

### 構造出來的證據(每一項單獨觸發)

| 情境 | 有效動作 |
|---|---|
| 只有 2 顆 D2 合格衛星 | **14/28** |
| 錨定格在格陣邊緣,缺 2 個鄰居 | **20/28** |
| 槽 0 的衛星在所有格的地平線下 | **21/28** |
| **完全沒有 D2 合格衛星** | **0/28** ⇒ **空遮罩,C-15 的 no-op 會觸發** |

已加成測試:`tests/test_w18_mask_can_bind.py`(五項,每一項單獨觸發)。

### 所以會發生在什麼情境?

三項各自需要:

1. **槽未佔用** —— D2 合格衛星 **< 4**。目前量到 `eligible_counts > 4` 恆成立
   (`test_the_d2_latches_are_warm_at_step_zero`),但那是**在 40°N、Starlink 密度下**。
   高緯度、極稀疏星座、或把 `Thresh2` 收緊(sweep 軸已有 900 km)都會觸發。
2. **格不存在** —— 錨定格落在格陣邊緣。目前不會,因為 `build_cell_grid` 帶了
   **一圈護欄環**,而護欄環的存在就是為了保證服務區內的格都有完整六鄰域
   (`missing = serves & (neighbor_ids == -1).any()` 會拋錯)。
   ⇒ **這一項在目前的格陣構造下確實不可能觸發**,而那是刻意的設計,不是意外。
3. **格看不到衛星** —— 需要衛星低於**格**的地平線,而不是使用者的。
   服務區只有 200×90 km,格心之間最遠約 220 km,所以四槽視窗裡的衛星
   幾乎不可能只對部分格可見。低仰角 pass 會逼近,但 D2 的 `Thresh2 = 1100 km ≈ 21°`
   已經先把它們排除了。

**⇒ 誠實的答覆:第 1 項與第 3 項是 (i) —— 有能力收縮,只是這組參數下沒發生;
第 2 項是 (ii) —— 護欄環讓它在建構上恆真。**

### 對論文的建議(不是裁決,是給你的輸入)

- §4.1 與 part1 p25 **不需要改寫成「恆真檢查」** —— 遮罩不是冗餘的,
  第 1 項與第 3 項都是真的約束;
- 但**應該揭露**在本情境下三項均不 binding,並說明是哪些場景參數讓它們不 binding
  (Starlink 在 40°N 的密度、`Thresh2 = 1100 km`、護欄環);
- **C-15 的空遮罩 no-op 不是死路徑** —— 它在 D2 合格數為 0 時會觸發,
  只是在這組參數下觀測不到。這一點值得寫成「機制存在且已測試,在本情境下未觀測到」,
  而不是「永遠不可能」。

**這一項我已經加進 PREREG 的 probe grid 當 P5**(逐項回報遮罩衰減),
所以「三項各自刷掉多少」會是凍結抽樣分布上的回報數字,不是一個手挑 epoch 的觀察。
