## 2. ⚠ 一項對 F-1 導出的事實修正:**參考點是 `θ(τ)`,不是波束軸**

`p⁰ = 0.825 W` 這個**值**不受影響,但裁決那張表隱含的前提在本實作裡不成立。

### 裁決的表

| 使用者位置 | 增益 | 需求功率 | 可行? |
|---|---|---|---|
| 波束軸 | `G_0` | 0.825 W | ✔ |
| 格邊緣(`θ = θ_3dB/2`) | `G_0/2` | 1.650 W | ✔ 剛好 `p_max` |
| 出格 | `< G_0/2` | `> p_max` | ✘ outage |

這張表算的是 `p_required = p⁰·G_0/G^T(θ)`,也就是把預算**對著波束軸**量。
那需要 `G^T(θ(τ)) = G_0`,即**每一個 segment 都從軸心開始**。

### (3.12) 不是這樣

```
p(t) = p⁰ · G^T(θ(τ)) / G^T(θ(t))
```

分子是**段起始那一刻的角度增益**,不是 `G_0`。segment 在使用者連上的那一步開始,
**當時角度是多少就是多少**,遞推只量「從那時起掉了多少」。

### 量測(600 個 segment,凍結情境)

| 量 | 值 |
|---|---|
| segment 起始的 `θ`,p50 / p90 / max | **1.165° / 1.673° / 2.143°**(`θ_3dB/2 = 1.660°`) |
| **起始就在 3 dB 圈外的 segment 比例** | **11.2%** |
| 段內增益跌幅,p50 / p95 / **max** | 0.026 / 0.277 / **0.718 dB**(預算 3.010 dB) |
| 平均 segment 長度 | 6.0 步 |

所以:

- 可行性檢查實際說的是「**你的增益比連上時掉了 3 dB**」,不是「你出格了」;
- 有 11.2% 的 segment **一開始就在格外**,而它們一樣以 `p⁰` 起跑、一樣可行;
- 段內最大跌幅只有 **0.718 dB**,離 3.010 dB 的預算很遠 ⇒ **這道閘目前不作用**。

### 這對 ch5 的影響

**`p⁰ = 0.825 W` 我建議照留** —— 導出的**結論**(3 dB 預算)是好的,
`p⁰/p_max/θ_3dB/R_b` 四量自洽這一點也成立,3 dB 之所以是對的尺度正是因為它是格的等高線。

**要改的是那句話的措辭。** 裁決寫「請在 ch5 寫出 `p⁰ = p_max/2` 的導出與
『3 dB = 格邊緣』的理由」—— 若照這樣寫,讀者會以為 outage ⇔ 出格,
而實作(與式 3.12)給的是 outage ⇔ 相對段起始掉 3 dB。兩者只在 `θ(τ) = 0` 時重合。

**建議措辭**:「`p_max/p⁰ = 2` 給每個 served segment **3 dB 的增益預算**;
3 dB 是波束自己的半功率等高線(`F(μ)=0.5` ⇔ `θ=θ_3dB/2` ⇔ `R_b`),
所以預算的大小由幾何決定而非任選。預算是**相對於段起始角度**量的。」

⚠ 附帶:若真的想要「outage ⇔ 出格」,那需要把遞推的參考點改成 `G_0`
(即 `p(t) = p⁰·G_0/G^T(θ(t))`),**那會改掉式 (3.11)(3.12) 本身**,
而 C-2 明講不引入這類替換。所以我沒有動,只報告。

## 3. F-2 的實作細節與一個措辭釐清

改成:

```
ξ_{s,v}(t)   = min{ ξ_max , ξ_max √( p_{s,v}(t) / p_sat ) }      去掉 u
P^p_{s,v}(t) = p_{s,v}(t) / ξ_{s,v}(t)                            去掉 u
P^N(t)       = P^f(t) + Σ_s Σ_v z_{s,v}(t) · P^p_{s,v}(t)        二重和,z 為過濾器
```

`system_power_w()` 的簽章隨之改為 `(supply_per_beam, radiating_beams_by_satellite)` ——
`served` 參數整個拿掉,因為 `z` 已經由「這支波束在不在陣列裡」承載,
和 `RadiatingBeams` 是同一個道理。它另外檢查兩個引數描述的是同一步
(波束數與逐衛星計數的總和必須相等),否則拋錯。

### `link_over_beam_power_ratio` 恆為 1.0 —— 我照裁決做了,但定義要講清楚

裁決說「改完後它應恆為 1.0,當成迴歸測試釘住」。
我把它定義為 **「回報的 `P^N` ÷ 獨立重算的逐波束 `P^N`」**,
所以它在改之前是 2.28、改之後恆為 **1.000000000000** ✓,並已釘進測試。

另外新增 `superseded_link_over_beam_ratio` 記錄**舊式會給的值**(2.107–2.626),
因為那是修正的幅度,是一項發現而不只是一個 bug。
裁決說的「比值就是平均每支波束載幾個人」量測完全吻合:
100 位使用者 / 41 支波束 = 2.44,落在 2.107–2.626 區間內。
