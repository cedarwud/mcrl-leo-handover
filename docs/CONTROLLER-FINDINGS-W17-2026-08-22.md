## ⛔ F-1 `p⁰ = 2 W` > `p_max = 1.65 W` ⇒ **outage 率恆為 1.0,沒有人被服務過**

### 事實

ch5 表 5-2(你 2026-08-22 依 C-12 重新歸屬後的 active 表)兩列:

| 符號 | 值 | 表上的說明 |
|---|---|---|
| `p⁰` | **2 W** | 「式 (3.11) 每個新 served segment 的**起始值**」 |
| `p_max` | **1.65 W** | 「式 (3.15a) 回退後的每波束操作上限,**亦為鏈路可行性檢查的門檻**」 |

### 為什麼這是硬矛盾

(3.12) 的段起始就是 `p(τ) = p⁰`,一個字面等式 —— 遞推在 `t = τ` 還沒有東西要補償。
而 C-2 定的可行性檢查是「`p > p_max` ⇒ 該步 outage」。

於是:**每一條鏈路在它的第一步就被判不可行** ⇒ 沒有段能走到第二步 ⇒
`z` 恆為空 ⇒ 沒有波束輻射 ⇒ `P^N = 0`、`r1 = 0`、系統永遠全黑。

`2 W` 比 `1.65 W` 高 **0.835 dB**。

### 量測(不是推論)

以凍結常數跑真實星曆,20 位使用者、10 步:

```
t=0  served   0  outage  20  beams   0  nobody served
...
t=9  served   0  outage  20  beams   0  nobody served
```

`outage_infeasible` 每步都是 **20/20**,`radiating_beams` 每步都是 **0**。

### 我做了什麼

- **照字面實作**,沒有偷偷調任何一個數。
- `link_budget.SEGMENT_START_EXCEEDS_BEAM_CEILING` 由兩個常數**算出來**(不是寫死),
  `segment_start_feasibility_report()` 回傳完整算式。
- 每一步的 `diagnostics` 都帶著這份報告。
- `StepEnvironment.assert_ready_to_train()` **在矛盾未解前拒絕開始訓練** ——
  probe 仍可跑,因為「outage 率恰好 1.0」正是這個裁決需要的證據。

| 選項 | 後果 |
|---|---|
| **(a) 可行性門檻改用 `p_sat = p_max·10^(BO/10) = 5.218 W`** | `p⁰ = 2 W` 有 4.2 dB 餘裕;鏈路只在 `G^T` 從段起始跌超過 4.2 dB 時才 outage。`p_max` 退回「標稱操作點」,ch5 那句「亦為鏈路可行性檢查的門檻」要改 |
| **(b) 降 `p⁰` 至 ≤ 1.65 W** | Table I 的 `p⁰ = 2 W` 是 **P 級(論文明列)**,改它是改論文參數 |

## ⚠ F-2 (3.16) 逐**鏈路**計電源功率,但一支波束只有一個放大器 ⇒ **`P^N` 高 2.28 倍**

### 事實

(3.16) 逐字是三重和:

```
P^N(t) = P^f(t) + Σ_{u'} Σ_{s'} Σ_{v'} x_{u',s',v'}(t) · P^p_{u',s',v'}(t)
```

`x` 是**連線**指示,所以這是「每條**被服務的鏈路**計一次 `P^p = p/ξ`」。

但 (3.12a) 前一句寫得同樣清楚:

> 一支已啟用的波束以單一功率發射,**不論其上載有幾位使用者**

一支波束 = 一個功率放大器 = **一份直流取用**。載 3 位使用者的波束不會取用三份電。

### 量測

以 100 位使用者跑真實星曆(43 支波束輻射):

| | 值 |
|---|---|
| (3.16) 逐鏈路計:`P^N` | **937.9 W** |
| 逐波束計(每支波束一份 `p_{s,v}/ξ`) | **412 W** |
| **比值** | **2.28×** |

20 位使用者時是 **1.41×**。比值 ≈ 已服務鏈路數 / 輻射波束數,
所以它**隨載量漂移**,不是一個常數偏移。

`r1` 就是 `R/P^N`,所以第一個目標被系統性壓低 2.28 倍,
而且壓低的程度**隨策略把使用者集中或分散而變** —— 這會直接進到梯度裡。

### 我做了什麼

- **照 (3.16) 逐字實作**(逐鏈路)。
- 同時每步算出逐波束版本,`diagnostics` 報 `beam_charged_power_w` 與
  `link_over_beam_power_ratio`,所以差距是**被量的**而不是被辯論的。

### 請裁決

`ξ` 本身已經是逐波束的(3.15a 用 `p_{s,v}`),只有 `P^p` 的求和是逐鏈路。
若這是筆誤,(3.16) 的和應改為對 `(s,v)` 且以 `z_{s,v}` 為門檻 —— 形狀會與 (3.16a) 一致:

```
P^N(t) = P^f(t) + Σ_{s'} Σ_{v'} z_{s',v'}(t) · p_{s',v'}(t) / ξ_{s',v'}(t)
```

**若你確認 (3.16) 就是要逐鏈路,我照舊,只是要在論文裡說明為何一支放大器計 U 次。**

## ✅ F-3 我自己的缺陷:載量以「格」為鍵而非「波束」(**已修**)

## 一項需要你點頭的實作解讀:(4.1) 的 `γ` 區塊用哪一步的干擾

(4.1) 把 `γ_{u,s,v}(t, θ(t))` 放在**每一個**候選位置上,同時要求
「只使用選擇動作前可取得的資訊」。這兩件事互相拉扯:本步的干擾取決於本步的啟用,
而啟用取決於本步的動作。

論文自己給了出口:「若實作使用 cached 或 predicted provenance,該標記放在資料欄位
metadata,不改變公式中的物理符號。」

**我的解讀**:候選 `γ` 用**當前幾何 `θ(t)`**(真的是動作前可得)配上
**前一步的輻射波束集合與功率**算干擾。provenance 命名為
`theta-current-interference-previous-step`,帶在 `StepObservation.sinr_provenance`
與每步 diagnostics 上,並會進 PREREG。

候選的分子一律用 `p⁰`(連上任一候選都是開新段,(3.12) 的段起始就是 `p⁰`)。
incumbent 原則上是例外,但我**沒有把它做成例外**:那會讓狀態的 28 個欄位混兩種功率來源
而沒有任何欄位標示哪個是哪個,而兩者的差就是該段累積的補償量,那已經由角度區塊承載了。

**若你要別的解讀,說一聲,這是一行的改動。**

## 順帶:兩個實作上的物理選擇,揭露為 `S`

1. **小尺度衰落逐(使用者, 衛星)抽,不逐波束。**
   衰落是傳播路徑的性質,同一顆衛星的每一支波束到同一位使用者走同一條路徑。
   逐波束抽會讓 wanted link 與它自己的同星干擾者**獨立衰落**,那不是通道模型,
   是往 SINR 上加變異。抽樣順序按 NORAD 排序,所以整個 episode 由種子唯一決定。

2. **(3.13) 的分子用 `p_{u,s,v}`,干擾用 `p_{s,v}`。**
   這是論文字面的不對稱:波束實際輻射 `max_u p_{u,s,v}`,
   所以不是最大值的那位使用者被記的 wanted 訊號**小於**該波束實際發出的。
   我照實作,沒有抹平 —— 而且它是保守的,誤差永遠指向較低的 SINR。
   (若 F-2 判為筆誤,這一項也許同源,可以一併看。)
