## 2. ⚠ argmax 一致率 9.56% 目前**無法解讀**,要補虛無基準

你把它當成「離『兩個目標永遠同意』很遠」的證據。方向對,但**基準設在錯的那一端** ——
該比的不是 100%,是**隨機一致率**。

而隨機基準在這裡不是 `1/28 = 3.57%`,因為 **`candidate_load_distinct_values` p50 只有 4**:
28 個候選只落在約 4 個相異載量值上 ⇒ **`r3` 的 argmax 大量平手**,
最佳集不是一個候選而是一群。

| `r3` 最佳集平均大小 | 隨機一致率 |
|---|---|
| 1 | 3.57% |
| 2 | **7.14%** |
| 3 | **10.71%** |
| 4 | 14.29% |

**實測 9.56% 落在「2 個平手」與「3 個平手」之間。** 也就是說,它可能完全就是
隨機值 —— 那樣的話這個指標**什麼都沒證明**,既不證明耦合也不證明分離。

**要補的:** 在同一份 P3 輸出裡回報
(a) `r3` 最佳集平均大小、(b) 由它導出的隨機一致率、(c) 平手怎麼打破。
有了 (b),9.56% 才知道是「2.7 倍於隨機」還是「就是隨機」。

⚠ **結論不會因此改變** —— 目標可分離這件事由 **+0.25 的相關係數**撐住,那個量沒有
平手問題。但「證據」要修,不能拿一個無法解讀的數字當論文裡的支撐。

⚠ 另外一件要寫進去、免得有人想把它調到 0:**`r1` 與 `r3` 殘留正相關是物理的,不是 bug。**
`R = B^w/U · log2(1+γ)` —— 波束上人越多,每人頻寬越少,吞吐量越低,EE 越低。
F-2 的缺陷是在這個物理耦合之外**又**加了一條經由 `P^N` 的假耦合。
現在的 +0.25 是前者,不是後者的殘留。

## 3. ⛔ `c_1` 與 `c_2` 沒有預註冊的選取映射 —— 這一項擋凍結

Q-D 關掉了 `c_3`。**`c_1` 與 `c_2` 沒有任何對應的 Q。**
`prereg_draft.py` 裡只有 Q-A、Q-B、Q-D、Q-E。

### 為什麼這會擋凍結

論文寫「`c_j` 由訓練開始前固定的非學習校準資料求得」。若 `c_1` 在凍結**之後**才由資料算出來,
那正是預註冊要防的那件事 —— 而且 `c_1` 不是無關痛癢的常數:
**有效取捨比例是 `ω_j/c_j`,所以 `c_1` 直接決定第一目標在純量化裡的份量,也就是頭條結果的平衡點。**

### 而且 legacy `c_1` 現在可以**證明**是錯的,不只是「過期」

| | 值 |
|---|---|
| `r1` 實測 p50(P3) | **508,681** |
| legacy `c_1` | **117,217,362** |
| 比值 | **230 倍** |
| 校準後 `r1` 中位數 | 0.0043 |
| 校準後 `\|r3\|` 中位數(`c_3=6`) | 0.500 |
| ⇒ 兩者失衡 | **115 倍,第一目標會被壓垮** |

我 ch5 寫的「`c_1` 依建構已失效」現在是**量測結果**,不是推論。

### ⚠ 而且 Q-D 的 p95 規則**不能**直接套到 `c_2`

`r2` 的分布:`p05 = −1.0`、`p50 = −0.0`、**`p95 = 0`**。
所以「取 `|r_j|` 的 p95」對 `r2` 會得到 **0 ⇒ 除以零**。

三個目標不能共用同一條統計規則。每一個都要有自己的規則**與理由**,就像你替 `c_3`
寫的那段(「p95 而非 max,因為 max 是單一壅塞波束,會讓尺度變成一個離群值的函數」)——
那段寫得很好,`c_1` 與 `c_2` 要各有一段同樣品質的。

### 要做的

**在凍結之前**,替 `c_1` 與 `c_2` 各建一個預註冊選取映射(Q-F / Q-G,或你偏好的編號),
規則凍在前、數字在後,由既有 probe 的輸出關閉(`c_1` 可由 P3 已經量的 `r1` 分布關閉,
不必新跑;`c_2` 需要一條與 `r2` 分布形狀相容的規則)。

**不要**現在就挑一個數字丟進去 —— 先凍規則。

## ⚠ 更正:原本的「發現一」是我誇大了

我原本把 `calibration_enabled = false` 另列成一個發現,說「照現況凍結會凍出退化的
訓練設定」,並附了純量化各項的倍數。**那是誇大。** 使用者指出:尺度差本來就是 `c_j`
要解決的,而 `c_j` 這個機制一直都在。我追進程式後確認他是對的:

- `reward_calibration_scales` 預設 `(1.0,1.0,1.0)`,且有守衛擋零值
  (「a zero scale divides the objective away without an error」);
- `calibration_enabled` 為真時,守衛會要求 `R3_SCALE_IS_FROZEN` —— Q-D 一關它就是 True;
- `reward_calibration_mode = "raw-unscaled"` 是**具名模式**,不是忘了設。

**機制完整,`calibration_enabled = false` 是常數未定時的誠實狀態,不是缺陷。**
那個倍數只是 §3 的量化,不是另一個問題。合併回 §3:它說明的是**`c_1` 若取錯會怎樣**
(legacy 值差 230 倍 ⇒ 校準後第一目標中位數 0.0043 對 `|r3|` 的 0.500),
而不是「現在就壞了」。

### 但有一個問題確實還在,而且是可查的

守衛涵蓋的是「**啟用校準時 `c_3` 必須已凍**」,**沒有**涵蓋「訓練時校準必須是啟用的」。
預設是關的、尺度是 `(1,1,1)`。

所以要問的是設計問題而不是缺陷指控:**凍結的那幾個 arm,`calibration_enabled` 應該是什麼?**

- 若兩個 arm 都該開,那 `c_1`/`c_2` 的映射就是凍結前置條件(§3 已裁),
  而且值得再加一條守衛:訓練時 `calibration_enabled` 必須為真;
- 若某個 arm 刻意跑 raw-unscaled(例如作為對照),那要在 PREREG 明寫**哪一個 arm、為什麼**,
  否則日後看不出那是選擇還是遺漏。

**這一項我只提問,不裁。**
