## 0. ⛔ `88.1%` 與 `1.6480 W` 對不上

預算 `= 10·log10(p_max/p⁰) = 10·log10(1.65/0.825) = 3.0103 dB`。

| | 峰值功率 | 換算跌幅 | 佔預算 | 你報的 |
|---|---|---|---|---|
| 暖啟動 OFF | 1.3786 W | 2.2298 dB | **74.1%** | 74.1% ✔ |
| 暖啟動 ON | 1.6480 W | 3.0050 dB | **99.8%** | 88.1% ✘ |

OFF 那列完全自洽,ON 那列差了 11.7 個百分點。若真的是 88.1%,對應功率是 **1.5194 W**,
不是 1.6480 W;而 1.6480 W 距 `p_max` 恰好 0.0020 W,與你自己寫的「距 p_max 0.002 W」
一致 —— **所以錯的是 88.1% 這個百分比,不是那個功率。**

我猜 88.1% 是另一個統計量(p99?排除掉判為不可行那些步之後的某個分位?)被誤放進
「max」那一列。**請確認並更正,兩個數字定案我才寫 ch5。**

⚠ 順帶注意一個結構性的事實:超過 `p_max` 的步會被判不可行 ⇒ 該步 outage ⇒
**可行步的峰值功率在建構上永遠 ≤ `p_max`**。所以「可行峰值 1.6480 W」逼近上限
不是巧合,那正是上限在削頂。這件事本身要寫進論文,否則讀者會把 99.8% 誤讀成
「差一點就爆」,實際上是「已經在爆了,爆掉的那些不在這個統計裡」。

### 但我需要一個數字才能決定那個警語要下多重

`L = 5` 是在 `H = 10` 的 episode 裡量的,**如果有相當比例的 segment 是被 episode reset
截斷的,那 L 本身就是被截短的**,真實段長大於 5,主臂的偏差就沒有看起來那麼大。

**請給 `Δt = 30.08 s`、雙時間尺度上線後的 segment 結束原因歸因**
(handover / outage / unserved / re-entry / episode reset 各佔多少)。

- 若多數由 **handover** 結束 ⇒ `L = 5` 是真實段長,主臂確實老一倍,警語要重;
- 若多數由 **reset** 結束 ⇒ `L` 被截斷,兩臂比表面接近,警語可以輕。

在這個數字回來之前,兩臂的處置照上面三點寫,但警語的強度我保留。
