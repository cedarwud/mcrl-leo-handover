## F-1 `p⁰ = 2 W > p_max = 1.65 W` ⇒ **改 `p⁰`,不改 `p_max`。定案 `p⁰ = 0.825 W`。**

### 先確認你的診斷

`10·log10(2/1.65) = +0.835 dB`,數字對。而且後果比「第一步不可行」更嚴格:
式 (3.11) 的遞推**在段內只會讓功率上升**(增益下降 ⇒ 比值 > 1),所以起點若已超限,
整段永遠不可能回到可行區。outage 20/20、beams 0 是唯一可能的結果,不是巧合。

### 為什麼動的是 `p⁰` 而不是 `p_max`

`p_max` 不是自由參數,它被放大器綁死:

```
p_sat = p_max · 10^(BO/10) = 1.65 × 10^0.5 = 5.218 W
```

而 `5.218 W` 正是 ch5 legacy 表裡的 `P_0`(PA 參考輸出功率)。也就是說
**`p_max` 是由「放大器飽和點 5.218 W」搭配「輸出回退 5 dB」導出的,不是挑的**。
動 `p_max` 會連帶動 `p_sat`,而 `p_sat` 出現在式 (3.15a) 的 `ξ` 分母裡 ——
會把 PA 效率曲線整條移位。所以 `p_max = 1.65 W` 不動。

`p⁰` 相反:它是情境常數,沒有任何物理量把它釘在 2 W。2 W 是舊 runtime 的執行值。

### `p⁰` 該取多少 —— 不要挑,用幾何導出

`p_max / p⁰` 這個比值有明確的物理意義:**一個服務分段在被判不可行之前,
最多能吸收多少增益下降**。因為段內 `p·G^T` 是不變量,

```
p(t) = p⁰ · G^T(θ(τ)) / G^T(θ(t))  ≤  p_max
  ⇔  G^T(θ(t)) / G^T(θ(τ))  ≥  p⁰ / p_max
```

所以問題變成:**我們要讓一個分段撐到哪裡?** 有一個答案是自洽的:**撐到格邊緣。**

- `F(μ) = 0.5` 恰好發生在 `μ = 2.07123`(這是半角慣例的來源);
- `μ(θ,θ_3dB) = 2.07123·sinθ/sin(θ_3dB/2) = 2.07123` ⇔ `θ = θ_3dB/2`;
- 而格半徑就是 `R_b = h_s·tan(θ_3dB/2)`。

⇒ **使用者站在格邊緣,等價於離軸角 `θ_3dB/2`,等價於增益掉 3 dB。**

取 `p⁰ = p_max / 2 = 0.825 W`,則:

| 使用者位置 | 增益 | 需求功率 | 可行? |
|---|---|---|---|
| 波束軸 | `G_0` | 0.825 W | ✔ |
| 格邊緣(`θ = θ_3dB/2`) | `G_0/2` | 1.650 W | ✔ 剛好等於 `p_max` |
| 出格 | `< G_0/2` | `> p_max` | ✘ outage |

**這讓可行性檢查有意義:它從「一個數值絆線」變成「你離開你的格了」。**
`p⁰`、`p_max`、`θ_3dB`、`R_b` 四個量因此互相自洽,而不是四個獨立挑的數。

**定案:`p⁰ = 0.825 W`,並在 ch5 寫出 `p⁰ = p_max/2` 的導出與「3 dB = 格邊緣」的理由。**

### 你要做的

- 常數改 0.825 W,重跑凍結 probe。預期 outage 率從 1.0 掉到「只有出格者 outage」。
- **請把新的 outage 率回報**,那是這條裁決是否成立的檢驗:若仍然接近 1.0,
  代表使用者初始分布本來就不在格內,那是另一個問題(格集選取,見 C-3),回報不要自己調。

## F-2 `(3.16)` 逐鏈路求和 ⇒ **改成逐波束求和。而且論文自己已經寫了鐵證。**

### 你的診斷成立,而且證據比你舉的更硬

你引 (3.12a) 前一句「一支已啟用的波束以單一功率發射,不論其上載有幾位使用者」——
對。但**更直接的證據在式 (3.15)/(3.15a) 自己身上**:

```
(3.15)   P^p_{u,s,v} = p_{u,s,v} / ξ_{u,s,v}          <- 分子帶三索引
(3.15a)  ξ_{u,s,v}   = min{ ξ_max , ξ_max √(p_{s,v}/p_sat) }   <- 引數只有 p_{s,v}
```

**`ξ` 的左邊帶著 `u`,右邊卻只有波束量 `p_{s,v}`,`u` 在右邊沒有任何對應物。**
論文已經把放大器當成逐波束的東西在算效率了,卻在下一條式子把它逐鏈路加總。
兩條相隔兩行的式子互相矛盾。

還有一個諷刺的旁證:式 (3.16a) 上方那句
「基頻功率由該衛星的所有啟用波束共用,因此**每顆衛星只計一次,不會重複計入**」——
論文明確意識到重複計入這個風險,並為 `P_BB` 防了一次,卻在放大器功率上犯了同一個錯。

### 你量到的比值就是診斷本身

| 使用者數 | 你量到的比值 | 隱含啟用波束數 |
|---|---|---|
| 100 | 2.28× | ≈ 44 |
| 20 | 1.41× | ≈ 14 |

**這個比值不是別的,就是「平均每支波束載幾個人」。** 逐鏈路加總把
`P^p_{s,v}` 重複計了 `U_{s,v}` 次,所以

```
Σ_links P^p  =  Σ_{s,v} U_{s,v}·P^p_{s,v}     vs     Σ_beams P^p = Σ_{s,v} P^p_{s,v}
```

比值 = 載量加權平均。你的兩組數字完全符合這個式子,診斷確定。

### 這個錯誤真正的傷害:它會汙染 P3

多出來的那一項是 `Σ_{s,v} (U_{s,v} − 1)·P^p_{s,v}`,**隨佔用人數單調上升**。
它出現在 `r1` 的**分母**,所以「波束越擠 ⇒ EE 越差」。

**但那正是 P3 的工作。** 換句話說,這個 bug 讓第一個目標偷偷兼做了第三個目標,
兩個目標不再可分離。這比「r1 整體偏小」嚴重得多 —— 常數偏移不影響 argmax,
載量相依的偏移會直接改變政策,而且會讓 `Ω=(0.5,0.3,0.2)` 的權重解讀失效。

### 正確形式

```
P^p_{s,v}(t)   = p_{s,v}(t) / ξ_{s,v}(t)
ξ_{s,v}(t)     = min{ ξ_max , ξ_max √( p_{s,v}(t) / p_sat ) }
p_{s,v}(t)     = max_{u∈𝒰: x_{u,s,v}(t)=1} p_{u,s,v}(t,θ_{u,s,v}(t))        (3.12a,不變)

P^N(t,θ) = P^f(t) + Σ_{s∈𝒮} Σ_{v∈𝒱} z_{s,v}(t) · P^p_{s,v}(t)
```

三處改動:

1. `ξ` 與 `P^p` **去掉 `u` 索引**(左右索引一致);
2. `P^N` 的三重和改成**對 (s,v) 的二重和**;
3. 過濾器從 `x_{u,s,v}(t)` 換成 `z_{s,v}(t)` —— 兩者等價
   (`z=1 ⇔ U>0 ⇔ 至少一條 x=1`),但 `z` 才是逐波束的正確過濾器。

`P^f` 的式 (3.16a) 不動,它本來就是逐波束 + 逐衛星計的。

### 你要做的

- 改成逐波束加總,`link_over_beam_power_ratio` **繼續每步回報**,改完後它應恆為 1.0,
  當成迴歸測試釘住。
- ⚠ `r1` 的數值會整體變大(分母變小),`c_1 = 117217362.202` 這個尺度常數會失準 ——
  但它本來就要等實驗重算,不用現在動。
