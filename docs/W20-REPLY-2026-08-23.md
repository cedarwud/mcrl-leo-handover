# 回覆 W-20:`88.1%` 的更正,以及 segment 結束歸因

**你抓到的矛盾是真的,而且原因比「放錯統計量」更具體 —— 那是兩個不同的量,
其中一個在暖啟動上線之後就不再有意義了。**

更正後的數字:**100.0%**,不是 88.1%。而且不可行步要的功率**中位數就是預算的 123%**。

## 0. `88.1%` 錯在哪裡

### 兩個量,不是同一個量的兩個統計

我的腳本算的 `peak` 是

```
max over the segment of  10·log10( g0 / g_t )
```

其中 `g0` 是**該 segment 在 episode 內第一次被觀察到**那一步的增益。

**暖啟動上線之前,那就是段起始,兩者相同。上線之後就不是了** ——
真正的 `τ` 在 episode 開始之前,而環境的 `link_power_w` 用的是暖啟動後的
`start_transmit_gain`。於是我的 `peak` **系統性低估**,而 `pmax` 是對的。

所以那不是 p99 被放進 max 那一列,是**一個在新情境下已經失效的量**還在被印出來。
`74.1%` 那一列自洽正是因為冷啟動下兩者相等 —— 你注意到 OFF 自洽而 ON 不自洽,
指向的就是這個。

### 更正:直接用 `link_power_w`,因為 `10·log10(p/p⁰)` **就是**已耗用的預算

重量(12 episode × 100 使用者 = **12,000 決策步**,雙時間尺度,`Δt = 30.08 s`):

| | 暖啟動 ON(主臂) | 暖啟動 OFF |
|---|---:|---:|
| outage | **95/12000 = 0.0079** | 0/12000 = 0.0000 |
| **可行**鏈路功率 p50 / p95 / **max** | 0.8250 / 1.1776 / **1.6498 W** | 0.7603 / 0.8426 / 1.4241 W |
| ⇒ 已耗用預算 p50 / p95 / **max** | 0.0% / 51.3% / **100.0%** | −11.8% / 3.0% / 78.8% |
| **不可行**步的**所需**功率 p50 / p95 / max | **1.9356** / 3.0746 / **3.3556 W** | (無) |
| ⇒ 需要的預算 p50 / max | **123.0%** / **202.4%** | — |

**ch5 用 100.0%,不是 88.1% 也不是 99.8%。**
(你從我上一輪的 1.6480 W 推得 99.8% 是正確的算術;這次重量的 max 是 1.6498 W,
因為 max 就是 max,樣本換了會動。兩者說的是同一件事。)

### ★ 你那個結構性提醒不只成立,而且量得出來

> 「超過 `p_max` 的步會被判不可行 ⇒ 可行步的峰值功率在建構上永遠 ≤ `p_max`。」

對,而且**被削掉的那一截有多大現在有數字了**:不可行步的**中位數**需要 1.9356 W ——
不是勉強超過,是**預算的 123%**;最極端的要 3.3556 W = **202.4%**,是上限的兩倍。

**所以「可行峰值 1.6498 W 距 p_max 0.0002 W」完全不是「差一點就爆」。**
分布的尾巴伸到上限的兩倍以上,上限把它從 100% 處切斷,
而我們只看得到切口。**這一段請務必寫進 ch5**,否則 100.0% 會被讀成驚險過關。

## 1. segment 結束歸因(`Δt = 30.08 s`,雙時間尺度)

| 原因 | 次數 | 佔比 | 那些 segment 的長度 p50 / mean |
|---|---:|---:|---:|
| **handover** | 1227 | **50.1%** | 6.0 / 5.54 |
| **episode reset** | 1200 | **49.0%** | 4.0 / 4.24 |
| outage | 22 | 0.9% | 1.0 / 1.00 |

**幾乎正好一半一半 —— 落在你那條判準的正中間。**

### 但「未設限」的估計把它解決了

只看**自然結束**的 segment(handover 或 outage,不含被 episode 邊界截斷的):

| | p50 | p95 | mean | max |
|---|---:|---:|---:|---:|
| **未設限段長(主臂)** | **6** | 7 | **5.46** | 7 |
| 未設限段長(OFF) | **6** | 7 | 5.69 | 7 |

而混合池(含被截斷者)的 p50 是 **5** —— 那正是被截斷拉下來的。

⇒ **真實段長是 6 步,不是 5 步。** 被 reset 截斷的那 49% 平均只跑了 4.24 步,
自然結束的那 50% 跑了 5.54 步。

### 對兩臂警語的含意:**中等,不是「重」**

主臂抽 `a ~ Uniform{0,…,9}`,平均段齡 **4.5 步**;
真實段長 6 步在平衡態下的平均年齡是 `(6−1)/2 = 2.5` 步。

**⇒ 主臂把段齡抽老了 1.8 倍,不是 2 倍。** 偏差方向仍如你更正我的
(往「讓約束更容易開火」偏),但幅度比 `L = 5` 暗示的小一點。

**建議警語強度:中等** —— 明說主臂偏向讓約束開火、給出 4.5 vs 2.5 這個對照,
但不必寫成「主臂可能整個造出了這個效應」。理由是敏感度臂不是唯一的對照:
不可行步中位數要 123% 的預算,那個超額**不是暖啟動造出來的**,
暖啟動只決定 segment 進場時已經走了多遠。

### ⚠ 連帶:敏感度臂凍的 `L = 5` 應該改成 6

`L` 的角色是更新過程的**真實**段間隔,而真實值量出來是 **6**(未設限中位數),
5 是被 episode 邊界截斷的混合池中位數。**凍 5 等於凍一個被截斷的估計。**

PREREG 尚未凍,所以現在改還來得及。**請裁:`segment_age_steps` 改 6 還是留 5?**
我傾向 **6**,理由是它是那個參數定義上要的量;但這會讓兩臂更接近
(主臂平均 4.5 vs 敏感度臂平均 2.5),**分歧會縮小而不是擴大**,
所以這個更正對「兩臂分歧是一項發現」這個敘述是**不利**的方向 —— 更該做。
