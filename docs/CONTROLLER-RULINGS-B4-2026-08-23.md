# 裁決:B4 —— `p_max = 1.65 W` 目前沒有出處(2026-08-23)

**這一項不是你們漏做,是我漏查。** 我逐輪驗的都是「實作 vs 我的裁決」,
從來沒有把 `DECISION-RECORD` 的 B1–B17 逐條對過實作。現在對完了,
17 條裡 14 條符合、2 條(B10/B11)已被後續使用者裁決取代,**只有 B4 是真缺口**。

## 1. 現況:三個互不相容的每星功率數字

| 來源 | 值 | 狀態 |
|---|---|---|
| **B4 決議**(2026-08-21) | `P_max = 50 dBm = 100 W`,依據 HOBS Table I | **從未實作**;論文與程式零命中 |
| ch5 legacy 表 | `P_sat,max = 10^(13/10) = 19.953 W` | legacy provenance |
| active 契約 | **無每星上限** | C-2 / C-12 |

而每波束 `p_max = 1.65 W`,在 `V = 39` 下單星滿載輻射 **64.3 W**:

- 超出 legacy 的 19.953 W **3.23 倍**;
- 但在 B4 的 100 W 之內。

⚠ `19.953 / 1.65 = 12.09` —— **`p_max = 1.65 W` 看起來是從一顆 12 波束衛星的預算來的。**
那個前提在 `V = 39` 之後不再成立,而 **ch5 對 `p_max` 沒有任何出處敘述**。

這不是無關痛癢的數字:`p⁰ = p_max/2 = 0.825`、`p_sat = p_max·10^{BO/10} = 5.218`、
以及 ch5 §5.1 整節的 outage 0.94% / 預算 99.6% / 尾巴 214.8%,**全部掛在它身上**。

## 2. 裁決:不採 B4 的上限,但用它給 `p_max` 一個出處

**不引入每星上限。** C-2 明寫論文不引入 beam/satellite cap,B4 若照字面實作會牴觸它,
而且會在遞迴之外再加一道閘 —— 那是我們花了好幾輪才拆乾淨的東西。

**改為把 B4 的數字當成一致性檢查,寫進 ch5:**

> 每波束射頻輸出上限 `p_max = 1.65 W`。在 `V = 39` 下,單顆衛星所有波束同時滿載
> radiates `39 × 1.65 = 64.3 W`,低於 HOBS Table I 的 LEO 最大發射功率
> `P_max = 50 dBm = 100 W`,因此該上限與參考文獻的每星功率預算相容。
> 本研究不另設每星上限(見式 3.11 下方的排除清單);此處僅作預算相容性檢查。

**這樣做的好處:**

- `p_max` 從一個無出處的數字,變成一個**與引用文獻對照過**的數字;
- 不引入任何新機制,C-2 完好;
- 而且它是可證偽的 —— 若哪天 `V` 或 `p_max` 變動,`V · p_max ≤ 100 W` 這條會自己失效。

⚠ **不要**把 `p_max` 改成 `100/39 = 2.56 W`。那會讓 `p⁰`、`p_sat` 與 ch5 §5.1
的全部數字重算,而 1.65 W 本身沒有被證明是錯的 —— 它只是沒有出處。
**補出處比換數字便宜,而且風險小。**

## 3. 要做的

- **你們**:把 `V · p_max ≤ 100 W`(HOBS Table I)寫成一個測試,
  這樣它就不只是論文裡的一句話 —— `V` 或 `p_max` 任一變動時會亮。
  順便在 `link_budget.py` 的 `BEAM_POWER_MAX_W` docstring 記下這個相容性檢查。
- **我**:ch5 的出處敘述我來寫。
- **`DECISION-RECORD`**:B4 標為「不採其上限形式,改為預算相容性檢查(2026-08-23 裁決)」,
  不要留成「已定案待實作」—— 那會讓下一個人以為還有一項沒做。

## 4. 這不擋凍結

`p_max` 的**值**不變,所以 PREREG 的凍結值一項都不動。
§3 是論文敘述與一個測試,可以與凍結並行。
