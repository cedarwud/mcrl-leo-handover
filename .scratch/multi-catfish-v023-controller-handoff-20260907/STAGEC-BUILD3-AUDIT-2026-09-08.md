## Decisive findings

1. **S3 can silently collapse to the additive decoder or impersonate S0.**
   - S3 only requires a non-null caller-supplied checkpoint string; it never compares that string with `model.checkpoint_sha256`: [deployment.py:675](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/deployment.py:675).
   - The selector accepts any object whose interaction head has `score()`. A read-only probe supplied a zero head, left `model.checkpoint_sha256=None`, passed `"a"*64`, and S3 accepted it and chose the additive BASE.
   - Context authentication checks changed users and physical actions, but not selected/incumbent Q1 values, affected-resource values, or global features: [deployment.py:605](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/deployment.py:605). Altered global features were accepted.
   - Consequently an exact-Ψ wrapper can make S3 behave as S0, while a zero head or laundered context makes it additive, without authenticated disclosure.

2. **T1/T2 use production classes but not the required integrated production path.**
   - T2’s helper builds action rows and trains the learner, but deployment tables and coalition contexts are then hand-constructed and passed directly to `ProfileSelector`: [test_contract_v1_acceptance.py:235](/home/sat/mcrl-v025-codex-ws-stagec/tests/stagec_v025/test_contract_v1_acceptance.py:235), [test_contract_v1_acceptance.py:629](/home/sat/mcrl-v025-codex-ws-stagec/tests/stagec_v025/test_contract_v1_acceptance.py:629).
   - T2 never enters `EvaluationRunner`; T1’s separate end-to-end smoke at line 608 is not the hand-computed T1 fixture.
   - The `omit_joint_context` facility exists but is never invoked: [test_contract_v1_acceptance.py:102](/home/sat/mcrl-v025-codex-ws-stagec/tests/stagec_v025/test_contract_v1_acceptance.py:102). Thus the mandated representation-failure half of T2 is absent.
   - T1’s alleged oracle removals actually require `CheckpointKnockoutExperiment`: [test_contract_v1_acceptance.py:440](/home/sat/mcrl-v025-codex-ws-stagec/tests/stagec_v025/test_contract_v1_acceptance.py:440), [test_contract_v1_acceptance.py:482](/home/sat/mcrl-v025-codex-ws-stagec/tests/stagec_v025/test_contract_v1_acceptance.py:482).

3. **T3 is a special merger path and its passing criterion accepts bad calibration.**
   - Mapping inputs to `merge_receipts` branch into `_merge_calibration_receipts`, bypassing the production file-receipt manifest, attempt registry, conformance, temporal-continuity, and complete policy-inventory checks: [merge.py:537](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/merge.py:537), [merge.py:614](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/merge.py:614).
   - It does reuse canonical row checks, `reaggregate_steps`, crossed inference, and claim logic; therefore it is not wholly parallel, but it is not the real merger path required by T3.
   - Calibration covers only 3% and 5% date SD—not 10%—and lacks the least-favourable conjunction null: [acceptance.py:99](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/acceptance.py:99).
   - It reports uncertainty at 5 and 12 seeds, but the reported 12-seed coverage is only `0.8783±0.0262` at 5% SD and `0.8933±0.0247` at 3% SD: [build report:31](/home/sat/mcrl-v025-codex-ws-stagec/V025-STAGEC-BUILD3-REPORT-2026-09-08.md:31).
   - The test merely checks that estimates lie in `[0,1]`, uncertainty is positive, and 24-seed power exceeds 5-seed power: [test_contract_v1_acceptance.py:980](/home/sat/mcrl-v025-codex-ws-stagec/tests/stagec_v025/test_contract_v1_acceptance.py:980). It never requires approximately 95% coverage or intended 5/12-seed power.

4. **Experiment schemas are structurally separate but execution semantics are not.**
   - Four distinct dataclasses and binding kinds exist: [experiments.py:11](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/experiments.py:11).
   - The runner accepts arbitrary model mappings and delegates all behavior to an evaluator; it does not verify source-map, checkpoint/model identity, neutral training, oracle removal, or knockout execution: [evaluation.py:1001](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/evaluation.py:1001).
   - Therefore a neutral-source execution can carry a self-consistent knockout binding, or vice versa. Receipts prove metadata agreement, not executed intervention semantics.
   - Oracle factor-score removal has no production runtime bound to its schema.

5. **BASE-first is locally implemented, not runner-enforced.**
   - `ProfileSelector.select_timed` validates BASE in the parent and kills the forked child correctly: [deployment.py:738](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/deployment.py:738).
   - But `EvaluationRunner` does not impose that method. Evaluators may call untimed `ProfileSelector.select`, choose another deadline, or use the exported thread-based `DeploymentAdapter`.
   - Thus the timer is owned by an optional selector wrapper, not guaranteed by the production runner as F2 requires.

6. **TRAIN and future-information controls are syntactic, not authoritative.**
   - Standard source shards and allocations reject literal non-TRAIN values: [shards.py:140](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/shards.py:140), [evaluation.py:156](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/evaluation.py:156).
   - The special T3 merger accepted a rehashed receipt whose embedded production unit said `split="TEST"` because that branch never checks the split.
   - World role is not checked against an external authoritative world manifest, so real TEST data can still be semantically mislabelled TRAIN.
   - Future-TLE and realised-fading restrictions are caller-supplied strings/digests. Resealing a feature derived from future information passes extraction; the digest proves only that the value was not changed after sealing: [state.py:176](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/state.py:176), [state.py:377](/home/sat/mcrl-v025-codex-ws-stagec/src/mcrl/stagec_v025/state.py:377).
