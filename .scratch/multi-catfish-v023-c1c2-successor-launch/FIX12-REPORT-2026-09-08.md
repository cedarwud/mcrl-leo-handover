## Result

The local-host tmux quoting defect is fixed without changing the science,
training or verification commands or their argument order, output paths,
write-once startup receipt schema, gate, or dry-run no-side-effect semantics.

The launcher now renders the controller body as a standalone shell program.
It sends those exact bytes through the existing `run_remote` path to the
server Python, which creates
`<checkout>/successor-controller-<session>.sh` with
`os.open(..., O_WRONLY | O_CREAT | O_EXCL, 0o700)`. Both `local` and SSH use
this installer and the same `%q`-quoted tmux start command. The startup JSON
is still created with O_EXCL and has its unchanged three-field schema. The
controller body uses a single-quoted Python heredoc, so no Python source is
nested inside tmux's quoted command argument.

Before tmux starts, the installed script's SHA-256 is checked against the
locally assembled bytes. The controller's first log line and the existing
`SUCCESSOR_SOURCE_TRAINING_LAUNCHED` line report that SHA-256; the latter also
reports the controller path.
