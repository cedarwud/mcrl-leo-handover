## A. ris.docx 的學生口氣特徵(讀其 ch4.2 方法段萃取,行 1358–1477)
1. **句子短、直述。** 例:「狀態:用來表示環境中每個元件目前的狀況。」貼完標籤接一句平鋪定義就收,不堆疊子句。
2. **「名詞:定義」清單式。** 列狀態/動作/獎勵/元件時用「狀態:… 動作:… 獎勵:…」貼標籤,不寫成綿密敘述段。
3. **連接詞樸素。** 因為…所以…、與…相比、而…、因此、接著、這樣。**不用**「各司其職 / 含混歸給 / 作用並不相同 / 在結構上就被擋住」這種精緻分析腔。
4. **順手解釋基礎概念(展現讀懂)。** 例:「γ 是折扣因子,決定未來 Q 值的重要性,通常介於 0.9 到 0.99。」
5. **公式用簡單引語帶。** 「…表示為:」「…定義如下:」「在時間步 $t$ 的狀態記為:」。
6. **claim 直接、少 hedge。** 直接說「本文方法做了什麼」。(但本專案 RED LINES 仍守 → 誠實用「預期 / 留待第五章」表達,**不要**用精緻 meta 句。)
7. **可接受一點不完美 / 中英混。** 行內 English 術語混進中文句(「該模型的 main agent 將會於 4.2.1 節介紹」)是這實驗室常態,不必打磨成期刊腔。

## B. ch4 要怎麼改(before → after)
- §4.1「框架中的估值與分配兩件事**各司其職,作用並不相同**。為了分辨各自的貢獻、**避免把效果含混歸給整體**,本文在 4.6 節…」
  → 「估值與分配這兩件事在框架裡負責不同的工作。為了知道各自的效果,本文在 4.6 節用一組對照實驗分開檢驗。」
- §4.2/§4.3 列東西時,多用「**名詞:定義**」清單(像 ris 的 State/Action/Reward),別寫成長段。χ_u 三個數值已接近,可更貼標籤。
- §4.4「這個流程的好處是…**藉此降低過度集中**」這類分析句 → 拆短、平鋪:「這樣每顆衛星最多開 $k_{\mathrm{cap}}$ 個波束,使用者不會全擠在同一個。」
- 通則:**長句拆 2–3 句**;去分析腔/精緻 meta;公式引語簡單化;基礎名詞順手解釋一句。
