## Scope and definitions

Family (coordinator's derivation, not re-derived here): pooled EE ≈ bits per lit beam, so a per-user unilateral score is
`score(a) = log2(1 + γ_a) − c·[N_a == 0]` (c = η·P_beam/B_w ≈ 4.2 bit/s/Hz by that derivation), with the `A m`
hysteresis hold layered on top exactly as `cf_sources.pick()` does (rank by the score; switch away from a legal
incumbent only if raw gain beats it by `10^(m/10)`). γ_a = raw `UserState.channel_quality` (block-2 nominal SINR; floor
at 0 never activated on these sets). **LP-prev**: N_a = raw `UserState.beam_loads[a]`, the previous-step user count
(simultaneous; a plain `SourcePolicy`). **LP-seq**: users decided in fixed order 0..99, N_a = users already assigned to
the same *physical* beam this step; candidate slots are per-user, so the beam key `(norad_id, cell_id)` is read from
`observation.candidates.slot_tables[u]` — the key `step.py::_observe` itself uses for `beam_loads` (PROGRESS.md,
"critical implementation finding"). Both variants step the environment once per step with the full joint action.
